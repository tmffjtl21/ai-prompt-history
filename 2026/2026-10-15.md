## 이슈와 배운 점
- sed `i\`/`c\` 명령에 빈 주소가 들어가면 전체 줄에 적용되어 파일이 깨진다. `ProductDetailServiceImpl`가 이렇게 깨져 git checkout으로 복구했다. 삽입 전 대상 줄을 먼저 확인하고 diff로 검증할 것.
- dnm-web 소스는 CRLF 줄끝이다. `$` 앵커 regex와 sed가 `\r` 때문에 전부 실패했다. 줄 끝 문자를 고려해 패턴을 짜야 한다.
- 긴 Bash 명령을 한 번에 넣으면 셸 파싱 오류로 아무것도 실행되지 않는다. 단계를 나눠 실행할 것.
- 임시 디버그 로그를 ERROR 레벨로 찍어 두면 에러 로그로 오인된다. 검증 후 제거 주석이 있으면 바로 걷어내거나 DEBUG로 둔다.
- 제거 작업 시 "호출부가 없는 필드"와 "타임딜 조건에 가려져 있던 공통 속성"을 구분해야 한다. `STK_DISP_YN`처럼 공통 속성인 경우 조건만 완화하고 필드는 살리는 쪽이 맞았다.
- 커밋 상태를 보고할 때는 git 상태를 직접 확인하고 말할 것. 상품고시정보 건을 미커밋으로 잘못 안내했다.
- Python이 없는 환경에서 xlsx는 PowerShell unzip 후 XML 파싱으로 읽을 수 있다. sharedStrings 인덱스를 맞춰야 한다.
- Chrome이 "CORS 오류"로 표시하는 것 중 상당수는 preflight가 서버에 도달하지 못한 경우다. HSTS 자동 승격은 브라우징 이력에 따라 PC마다 다르게 나타난다.
