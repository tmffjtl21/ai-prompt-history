## 이슈와 배운 점
- 마일리지 전체 제거는 SQL·DTO·enum까지 걸려 프론트·SAP 정합 리스크가 크다. "외부 API 호출부만 끊기"로 범위를 좁히는 것이 안전했다. 넓은 변경은 stash로 보관해 두면 되돌리기 쉽다.
- 라이브러리(dnm-sap, dnm-erp)는 Jenkins가 아니라 GitLab CI가 Nexus에 올린다. 새 GitLab 프로젝트는 Runner가 할당되지 않아 pending에 걸리므로 Settings > CI/CD > Runners에서 확인해야 한다.
- GitLab CI가 `src/` 변경 검사를 하므로 `.gitlab-ci.yml`만 추가한 커밋은 배포되지 않는다. 수동 실행 시 검사를 건너뛰도록 해 두었다.
- Nexus에 SNAPSHOT이 없는 상태에서 앱 pom에 의존성을 넣고 Jenkins 배포하면 의존성 해석 실패로 빌드가 죽는다. 라이브러리 배포가 먼저다.
- Next.js `⨯ fetch failed ECONNRESET`은 서버 측 fetch 실패다. 개발 서버의 외부 HTTPS 아웃바운드 차단이 원인이었고, 이미지 최적화가 매 요청마다 실패한다.
- `next start`는 NODE_ENV가 production이라 로컬(`next dev`)과 Secure 쿠키·미들웨어 판정이 달라진다. HTTP 배포 환경에서는 NODE_ENV가 아니라 실제 프로토콜(`x-forwarded-proto` 포함)로 판정해야 한다.
- dnm-web은 국내 Redis(10.22.51.189)를 보고 있었고 해외 서버에서는 접근 불가였다. 환경 파일의 인프라 주소는 배포 서버 기준으로 다시 확인해야 한다.
- `MileageLocalCallAspect`는 마일리지 호출 전용이었고, 재고 등 다른 core 호출은 처음부터 HTTP + 보상 방식이다. 커밋 단계 실패 시 보상이 안 도는 창은 기존 한계다.
