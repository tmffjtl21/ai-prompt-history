## 이슈와 배운 점
- **배치 공유 락**: REPEATABLE READ 에서 `INSERT ... SELECT` 는 원본 행에 공유 next-key 락을 잡고 트랜잭션 끝까지 유지한다. 풀스캔이면 테이블 전체가 잠긴다. 해당 트랜잭션만 READ COMMITTED 로 지정하면 락 없는 읽기가 된다.
- **데드락 vs 락 대기**: 배치가 먼저면 락 대기(50초 후 그 문만 실패), 주문이 먼저 시작해 교차하면 데드락(즉시, 트랜잭션 전체 롤백, 변경 행 적은 주문이 희생). 어느 쪽이든 예외는 INSERT 문에서 나므로 catch 의 보상은 실행된다.
- **MySQL 8 갭 락**: 유니크 인덱스 범위 조회의 상한 다음 갭은 잠그지 않는다. 배치가 supremum 까지 잠근 것은 풀스캔·서브쿼리 lookup 때문.
- **RR 의 locking read**: `INSERT…SELECT` 는 스냅샷이 아니라 최신 커밋본을 읽는다. 스냅샷 규칙은 일반 SELECT 에만 적용된다.
- **데이터 보정 시 추측으로 컬럼을 늘리지 말 것**: `employee_yn`, `stf_seq` 는 원래 정상값이었다. 필요한 컬럼만 바꾼다.
- **파이프라인 브랜치 규칙**: `BRANCH` 파라미터가 common·sap-client·core 에 그대로 적용되어 소스를 직접 빌드한다. 브랜치 간 수정 누락이 곧 dev 장애로 이어지므로 cherry-pick 으로 맞춘다.
- **깨진 커밋 cherry-pick**: 원본 커밋에 상수 선언이 빠져 있어 cherry-pick 한 브랜치도 함께 깨졌다. 커밋 전 컴파일 확인이 필요하다.
- **enum 상호 참조 NPE**: 두 enum 이 생성자에서 서로를 참조하면 클래스 초기화 순서에 따라 필드가 null 로 굳는다. 필드 대신 메서드로 참조한다.
- **yml `logging.level` 이 logback 을 덮어쓴다**: `org.hibernate.SQL: DEBUG` 처럼 yml 기본 블록에 남은 항목은 logback 프로파일 설정으로 못 끈다.
- **ELB 헬스체크는 2xx 만 정상**: `GET /` 에 401 이나 404 를 주면 unhealthy 로 잡히고, 404 는 스택트레이스까지 남긴다.
