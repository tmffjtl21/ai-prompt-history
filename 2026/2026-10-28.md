## 질문과 답변 기록

- **[11:14] Q.** 통합회원 호출 쪽 토큰이 만료된다는 메일이 왔는데 어디서 호출하는지 찾아줘
  **A.** 호출은 api-bo `IntegratedMemberApiService`(2개 API), batch-mbod `MemberSyncServiceImpl`(7곳), `MemberSyncTestController`(4곳)다. 토큰은 설정 키 `ow.member.token`으로 Bearer 헤더에 실리는 JWT이며 운영용은 2026-12-31 만료다. 값은 api-bo·batch-mbod `application.yml`과 batch `config/application-*.properties`에 프로파일별로 하드코딩돼 있다. SAP/CIMS 연동과 사용자 JWT 검증용 설정은 영향 없다.

- **[11:22] Q.** batch-mbod를 인텔리제이로 열었는데 소스가 안 보이는데 뭐가 문제지?
  **A.** `.idea/modules.xml`이 참조하는 `x2bee-batch-mbod.iml`이 디스크에 없어서다. `*.iml`이 gitignore 대상이라 모듈 정의가 사라지면 소스 루트를 못 잡는다. Maven 도구창에서 Reload All Maven Projects 하면 재생성된다. 안 되면 `.idea`를 지우고 `pom.xml`을 Open as Project로 다시 연다. 사내망에서 Maven wrapper 다운로드가 막히면 Maven home을 로컬 설치본으로 바꾼다.

- **[13:20] Q.** develop, stage, production, dev-gerp 브랜치에 api-bo, batch, batch-mbod 커밋 반영했는데 맞나 봐줘
  **A.** 스테이지 배포 진행해도 된다. api-bo는 네 브랜치 모두 새 토큰이고, batch는 원격에 dev-gerp와 dev-monolith만 있어 dev-gerp의 properties 5개가 새 토큰이다. batch-mbod dev-gerp는 core 모듈이라 yml이 없어 바꿀 게 없다. 새 토큰은 주체가 `new-mall`에서 `mall`로 바뀌었으니 배포 후 호출 테스트를 권한다.

- **[14:21] Q.** 글로벌은 우선 두고, x2bee 쪽은 다 처리됐고 origin push도 됐는지 봐줘
  **A.** 전부 push됐고 커밋 안 된 변경도 없다. api-bo stage만 원격이 2커밋 앞서는데, 14:05에 다른 개발자가 `feature/ecc/BO-JHJ-1008`을 머지한 것이고 토큰 커밋은 원격에 포함돼 있다. 배포 전 `git pull`로 로컬 stage만 맞추면 된다.

- **[15:13] Q.** x2bee_global dnm-web에서 머지 abort 하려면 어떻게 해? 다시 돌리고 싶어

## 이슈와 배운 점
- 통합회원 토큰이 레포마다 프로파일별 yml·properties에 하드코딩돼 있어 교체 지점이 많다. 한 곳에서 관리하는 구조로 바꾸면 재발 부담이 준다.
- 새 토큰은 subject가 `mall`로 바뀌었다. 통합회원 쪽이 username 단위로 권한을 주면 계정이 달라진 것이므로 배포 후 반드시 호출 확인이 필요하다.
- IntelliJ `.iml`은 gitignore 대상이라 clone 직후나 캐시 삭제 후 사라질 수 있다. 소스가 안 보이면 pom보다 Maven reload를 먼저 시도한다.
- `git merge --abort`가 안 먹으면 `MERGE_HEAD` 존재 여부와 reflog를 먼저 본다. stash pop 충돌은 머지 상태가 아니다.
- 오래된 stash를 최신 develop에 바로 pop 하면 대량 충돌이 난다. `git stash branch`로 stash 시점 브랜치를 따서 적용 후 머지하는 편이 낫다.
