## 이슈와 배운 점
- **DataSource 다중 빈**: `@Autowired(required=false)`는 빈 0개만 허용하고, 여러 개에 `@Primary`가 없으면 기동 실패다. 공용 라이브러리는 `ObjectProvider`와 빈 이름 설정으로 호스트 환경에 독립적이어야 한다.
- **IDE stash 함정**: IDE의 pull 전 stash가 미커밋 작업을 통째로 숨겼다. 수정 뒤 install이 다시 돌아 옛 코드가 `~/.m2`에 덮어써졌다. 작업 중간에도 커밋을 만들어 두는 것이 안전하다.
- **SNAPSHOT 의존성**: 배치·BO는 dnm-erp를 Nexus SNAPSHOT으로 받는다. 수정 후 install 또는 push 없이 띄우면 같은 오류가 재발한다. IDE는 Maven 리로드가 추가로 필요하다.
- **예외 삼키는 aspect**: AS-IS에서 온 매퍼 aspect가 예외를 null로 바꿔 `AopInvocationException`만 남겼다. 원인 SQL 메시지가 보이도록 예외를 그대로 던져야 한다.
- **dev DB 복제 데이터**: 국내 복제 데이터 때문에 `CIMS_CLIENT_NO` 기준 UPDATE가 PK 중복으로 실패했다. PK 기준 ODKU가 안전하다.
- **XML 선언과 T-SQL**: `near '1.0'` 오류는 파라미터 바인딩이면 발생하지 않는다. EAI 또는 SP의 동적 SQL 가능성이 크고, 이 SP의 XML 처리 구간이 실제 호출된 첫 사례다.
- **자격증명 규칙**: 비밀번호는 설정 파일에서 읽지 않고 사용자에게 받는다.
