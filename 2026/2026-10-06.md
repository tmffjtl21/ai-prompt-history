- **[17:58] Q.** `java: No enum constant javax.lang.model.element.Modifier.SEALED` 이거 무슨 오류야?
  **A.** 컴파일 JDK가 17 미만인데 Lombok 1.18.34가 JDK 17부터 있는 `SEALED` 상수를 찾아서 나는 오류다. `.idea/gradle.xml`이 `delegatedBuild=false`라 IntelliJ 자체 컴파일러가 빌드하고, PC에 JDK 8, 17, 21이 있고 JAVA_HOME은 비어 있다. Project SDK, Module SDK, Gradle JVM을 corretto-21로 맞추면 된다.

- **[18:01] Q.** language level이 최대가 18인데.
  **A.** 그게 진짜 원인이다. 설치된 IntelliJ 2022.1.4는 Java 18까지만 알고 JDK 21을 모르므로 번들 JBR(JDK 11 기반)로 빌드해 `SEALED`를 못 찾는다. IntelliJ 2023.2 이상으로 업데이트하거나, Build and run을 Gradle 위임으로 바꾸고 Gradle JVM을 corretto-21로 지정하면 우회된다.

## 이슈와 배운 점
- **판촉물 판별 기준은 유형코드 하나다.** `goods_typ_cd='50'` 외 별도 플래그가 없어 제거 범위를 식별자 패턴으로 전수 조사해야 잔재가 남지 않는다.
- **공용 테이블 주의.** `pr_ord_dtl_atch_file_info`와 OM065는 클레임 첨부도 쓰므로 판촉물 전용으로 오인해 지우면 안 된다.
- **제거 순서가 중요하다.** BO → goods → order → 공용 enum → DB 순서로 해야 중간에 컴파일이 깨지지 않는다.
- **코드와 DB를 같이 적용해야 한다.** 품목검색의 유형 50 제외 조건을 뺐으므로 상품 삭제 SQL 없이 배포하면 판촉물이 일반 상품처럼 노출된다.
- **dnm-web 호출 잔재.** 로그인 직후 design-confirm 엔드포인트 호출이 남아 있어 404가 발생한다. react-query 에러로 끝나 화면은 깨지지 않는다.
- **WARN 로그 위치.** `SapClientException`, `AppException` 핸들러는 WARN으로 찍어 `x2bee-api-error.log`에 남지 않고 `x2bee-api.log`에서 찾아야 한다.
- **응답 출처 구분법.** Windows JVM은 timestamp 소수점 7자리, Linux JVM은 9자리를 찍는다. 이걸로 로컬 응답인지 서버 응답인지 구분할 수 있다.
- **SAP ZA01 주문유형은 주문사유(AUGRU)가 필수다.** `SD0020OrderRequest`에 `augru` 필드는 있지만 `PayWayStrategy.buildSD0020Order`에서 채우지 않아 어느 환경이든 재현된다.
- **api-order 테스트가 Maven으로 안 돈다.** surefire에 `skipTests=true`가 박혀 있고 `@SpringBootTest` 20개는 부트 설정이 없어 컨텍스트가 뜨지 않는다.
- **스키마 불일치 가능성.** shell 프로파일은 `x2bee_main2`, 조사와 SQL은 `g_x2bee_main`이다. 두 스키마 모두 판촉물 테이블이 있다.
- **IntelliJ 2022.1.4는 Java 21 미지원.** Language level 최대 18이며 dnm-gerp만 Java 21을 써서 여기서만 걸린다.
