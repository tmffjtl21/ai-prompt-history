## 이슈와 배운 점
- **묻지 않고 구조를 바꿈**: CORS가 막힌 것을 보고 AI가 우회 route를 임의로 만들었다. 개발자가 지적해 되돌렸다. 외부 제약은 우회하지 않고 기존 방식대로 구현한 뒤 요청할 것만 보고하기로 했다.
- **IAM CORS 미등록**: 스테이지 IAM `sso-token`은 `http://us.stg.osstem.com:9090`만 허용한다. CORS는 스킴·호스트·포트가 정확히 일치해야 하므로 요청 시 실제 접속 주소로 적어야 한다.
- **Spring 프로파일 지정**: shell에서 `spring.profiles.active=local,iam`처럼 콤마로 주면 기동이 실패한다. `active`와 `include`를 나눠 준다.
- **`.env` 줄바꿈 누락**: `.env.local.iam`에서 `NEXT_PUBLIC_SSO_TOKEN_URL`과 `NEXT_PUBLIC_SSO_LOGIN_URL`이 한 줄로 붙어 있었다. 로그인 URL이 읽히지 않는 상태였다.
- **`.next` 잔재**: 삭제한 route의 생성 타입 파일이 `.next`에 남아 타입 체크가 걸렸다. 잔재를 지우고 통과했다.
- **dev 서버에서 IAM 미도달**: 개발 서버(10.10.12.54)에서 IAM이 닿지 않는다. dev는 정적 JWKS 파일 방식으로 유지했다.
- **쿠키명 변경과 env 전환의 배포 순서**: 로그인 URL이 구 멤버스인 HTTPS 스테이지에 쿠키명만 바꿔 배포하면 로그인 루프가 난다. env 전환과 같이 나가야 한다.
- **dev DB 접속 거부**: MCP 접속이 거부돼 테이블 컬럼을 직접 확인하지 못했다. 테스트 SQL은 국내 stage 스키마와 BO 동기화 매퍼 기준 추정이다.
- **SSH 호스트 키 변경 경고**: 서버 호스트 키가 바뀌면 접속이 막힌다. `known_hosts`의 해당 항목을 지우고, 새 지문을 확인한 뒤 등록한다.
