## 이슈와 배운 점
- **EAI Idempotency-Key 고정 재전송**: 같은 키로 재전송하면 첫 실패 응답이 그대로 돌아온다. 생성 테스트는 매번 새 주문번호와 새 키로 보낸다.
- **쓰기 IF 이중 호출**: 조회 엔드포인트의 "예제 1·2" 패턴을 쓰기 IF 에 그대로 쓰면 주문이 두 번 들어간다. 쓰기 IF 는 `execute` 한 번만 호출한다.
- **NETRA 계약 잔액 검증**: "Order amount is more than contract amount" 는 SQL 오류가 아니라 업무 검증이다. IF-PKG-001 로 주문가능금액을 먼저 조회한다.
- **IF-ORD-003 정의서 오타**: 에러코드 키가 `r_err_cod` 다. DTO 도 오타 그대로 맞췄다.
- **x-forwarded-for 처리 방향**: 접근 제어는 맨 뒤 항목을 써야 위조를 막는다. 로그 용도 코드(dnm-gerp)를 그대로 가져오면 안 된다.
- **스테이지 Redis 읽기 전용**: `set` 이 조용히 실패해 스테이지는 매번 S3 를 직접 읽는다. 스테이지 테스트 결과로 운영 절차를 판단하면 안 된다.
- **S3 이미지 서버 1년 캐시**: 브라우저로 `maintenance.json` 을 확인하면 옛 값이 보인다. curl 로 확인하거나 업로드 시 `--cache-control "no-cache"` 를 준다.
- **Next.js dev 서버의 `::1`**: 로컬 요청에 `x-forwarded-for: ::1` 이 자동으로 붙어 `127.0.0.1` 허용 목록으로 통과한다. "로컬 브라우저는 무조건 점검 페이지" 라는 앞선 설명과 env 주석은 틀렸다.
- **next.config.ts 의 env 덮어쓰기**: `.env.local.set` 값이 `process.env` 를 덮어써 셸 환경변수로는 S3 주소를 바꿀 수 없다. 별도 `.env.localtest` 와 `APP_ENV` 로 우회했다.
