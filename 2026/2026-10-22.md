## 질문과 답변 기록

- **[11:24] Q.** 현재 시스템의 API 인증을 설명하는 문서를 PPT로 만들어 줄래? (스프링 시큐리티 기본, 내부·외부 인증, Basic 인증)
  **A.** 18장 PPT를 완성했다. 1부는 서블릿 필터 체인과 Authentication 구조, ThreadLocal 기반 `SecurityContextHolder`와 비동기 주의점. 2부는 체인 4개 선택 순서(@Order -1 ignore / 0 Basic / 1 내부 / 2 외부), 외부 인증의 JWT 처리 흐름과 401/403 판정, 내부 인증의 서비스 토큰(HS256, 60초, ROLE_SERVICE) 검증. 3부는 HTTP Basic 원리와 extApiFilterChain(`/api/goods|order/v1/ext/**`, InMemory 계정 1개, ROLE_EXT_API). 정리로 세 방식 비교표, 실패 응답 형식, 새 API 추가 시 체크리스트를 넣었다. 작업 트리에 Basic 체인 삭제 미커밋 변경이 있어 의도 확인을 요청했다.

- **[12:30] Q.** 서블릿은 자바 기술이고 필터도 그 스펙에 들어가 있고, 그걸 이용하는 게 스프링 시큐리티지?
  **A.** 맞다. 서블릿은 Jakarta EE Servlet 명세로 정의된 자바 표준이고 `Filter`, `FilterChain`도 같은 명세의 일부다. 스프링 시큐리티는 컨테이너에 `DelegatingFilterProxy` 하나만 등록하고, 이것이 `FilterChainProxy`로 위임해 `SecurityFilterChain`을 골라 실행한다. Tomcat 입장에서는 스프링 시큐리티가 필터 한 개다.

- **[12:31] Q.** 근데 WebFlux는 서블릿을 안 쓰지 않나?
  **A.** 맞다. WebFlux는 Netty 기반 리액티브 스택이라 서블릿 필터를 쓰지 않는다. 스프링 시큐리티도 WebFlux용으로 `SecurityWebFilterChain`, `WebFilter`, `ReactiveSecurityContextHolder`를 따로 제공하며 ThreadLocal 대신 Reactor Context로 SecurityContext를 전달한다. 워크스페이스에서는 `aurora-x2bee-gw`(Spring Cloud Gateway)가 WebFlux이고, `aurora-x2bee-api`, `api-bo`는 Spring MVC라 서블릿 필터 구조가 맞다.

- **[13:00] Q.** 파일 처음에 JSB는 뭐야?
  **A.** 표지의 J·S·B 칩은 세 인증 방식의 머리글자다. J는 JWT(외부 인증, 주황), S는 Service token(내부 인증, 파랑), B는 Basic(외부 연동 API, 보라). 이 색 규칙은 뒤 슬라이드의 태그, 번호 칩, 비교표 머리글에 동일하게 반복된다. 표지에 설명이 없어 설명 문구 추가 또는 제거를 제안했다.

- **[13:33] Q.** 색상을 초록색 말고 좀 밝은 톤으로 안 될까?
  **A.** 답변 없음. 주간 사용량 제한에 걸려 처리되지 않았다(1am KST 리셋).

## 이슈와 배운 점
- pptxgenjs로 만든 파일에 높이가 음수인 화살표 선이 있으면 PowerPoint가 파일을 열지 못한다. 도형 좌표는 양수로 정규화해야 한다.
- Python, LibreOffice가 없는 환경에서는 pptx 스킬의 validate.py 대신 PowerPoint COM으로 슬라이드를 PNG로 내보내 시각 검수할 수 있다.
- 작업 트리와 커밋본이 다를 때 문서의 기준을 명시해야 한다. 이번에는 Basic 인증 체인이 작업 트리에서 삭제돼 있어 커밋본 기준으로 작성하고 확인을 요청했다.
- 현재 작업 트리 상태로는 컨트롤러의 `@Secured("ROLE_EXT_API")`와 yml의 `ext-api.*`만 남아 `/v1/ext/**` 호출이 전부 거부된다.
- Spring Security의 서블릿 필터 구조는 MVC 스택 얘기다. WebFlux(게이트웨이)에는 `WebFilter` 계열이 따로 있고 ThreadLocal 전제가 다르다.
